The problem

“It works on my computer”

You write code. It runs. You send the same file to a classmate and it fails on their machine. Not one character of your code changed. The computer changed.

Reason 1

A different Python version

Your machine has Python 3.12. Theirs has 3.9. Some code that is correct in one version is an error in the other.

Reason 2

A missing library

Your code uses a library (a package of code someone else wrote). You installed it months ago and forgot about it. Their machine does not have it.

Reason 3

A different library version

You both have the library, but yours is version 15 and theirs is version 10. The function you use may not exist in version 10.

The real cost

This is not a small annoyance. In a team project it is the difference between "we finished it" and "it only runs on one laptop". Every part of today's class is an answer to this one slide.

What we install today

Three tools, three different jobs

People say "I installed Python" and mean all three of these. They are separate programs with separate jobs. Know which one you are talking about.

Editor

VS Code

Where you write and read code. On its own it is only a text editor. We also install the Python extension (an add-on that gives VS Code a new skill) so that it understands Python files.

Runtime

Python

The program that actually runs your file. Its other name is the interpreter (the program that reads your Python file and does what it says). VS Code does not run code. Python does.

History

Git

Saves every version of your work, with a note about why it changed. We install it today and only check its version number. You use it in Chapter 4.

One thing to remember

An installer adds the new tools to PATH (the list of folders where Windows looks when you type a program name). A terminal reads PATH once, at the moment it opens. So a terminal that was already open does not know the new tools exist. After the install, open a new terminal.

The main idea of today

A virtual environment is
one box per project

A virtual environment (a separate box of libraries for one project) lives inside your project folder. Libraries you install go into that box, and nowhere else.

Without a box

Every library you install goes into one shared pile on the whole computer. Project A needs version 15 of a library. Project B needs version 10. The shared pile can hold only one of them, so one project breaks.

With a box

Project A has its own box with version 15. Project B has its own box with version 10. Neither project knows about the other. And you can delete a box and build it again in one minute.

How the box travels

requirements.txt is the list
of what is in the box

A box is useful on your own machine. A written list of what is inside the box is useful to everyone else.

rich==15.0.0
pandas==3.0.5
requests==2.34.2
  • One library and one version on each line. The version number is the important part.
  • Your classmate types one command — pip install -r requirements.txt — and gets the same box you have.
  • This is the answer to slide 3. The three reasons code breaks were the Python version, a missing library, and a wrong library version. This file fixes the last two. The Python version comes from the installer — everyone here has 3.12.

The skill this course teaches

How to ask AI: four steps

Everyone here has used an AI chat. Few people use it well when code fails. These four steps are the difference, and they are the same in every AI tool.

Paste the error exactlyCopy the whole error text and paste it. Do not shorten it, and do not describe it in your own words. The exact text holds the file name, the line number and the error type — that is what the AI reads.
Add one line: what you were trying to do"I wanted to print a green word." The error says what broke. Only you can say what you wanted.
When you get an answer, ask why"Why does the new code work?" A fix you do not understand will break again in ten minutes, and you will be back at the same place.
Explain the fixed code yourselfSay it out loud to the person next to you. If you cannot explain it, you are not finished — go back to step three.
Which AI

ChatGPT, Gemini or Claude — use whichever one opens in this browser. Try ChatGPT first: it answers without signing in. This course does not teach one company's tool. It teaches you how to ask.

Click in the AI chat box (or a GitHub issue) and press Ctrl + V. Text is still better when you can copy it: the AI reads text more exactly than a picture.

What is allowed, and what is not

What AI is for,
and what it is not for

This is not a speech about honesty. It is a grading rule, and it is the same one you heard in Chapter 2.

Yes

Use AI for these

Reading an error message and telling you what it means. Answering a question about a concept. Fixing your English grammar. Explaining what a piece of code does.

No

Do not use AI for these

Making a whole assignment for you. Handing in code you cannot explain. Pasting an AI answer into your work without checking that it is true.

The grading rule

If you cannot explain it, it does not count. I will ask you why your code works. "The AI said so" is not an answer. This is true for every assignment this semester — and it is why step four exists.

Why this is fair

Professional developers use AI every day. Nobody is asking you to work without it. You are asked to stay the person who understands the code, because you are the one who has to fix it at eleven at night.

PART 0

Check the account, then install

15 min

Every PC in this room uses one shared Windows account, so we check whose GitHub account this browser is holding before we touch anything else. Then we install the three tools.

  1. Open github.com and look at the top-right corner. If the avatar there is not yours, click it, choose Sign out, and sign in with your own account. If nobody is signed in, sign in now.
  2. Open course-notice › Releases › Lab setup and click labsetup.zip. It goes to your Downloads folder.
  3. Open the Downloads folder. Right-click labsetup.zip, choose Extract All…, then Extract. A folder named labsetup opens.
  4. In that folder, double-click install.bat. If Windows shows “Windows protected your PC”, click More info, then Run anyway.
  5. It asks you nothing. First it downloads the three installers from their official servers (about 330 MB) and checks each file. Then it installs them. The whole run takes about 5 to 10 minutes. Do not close the window until it prints DONE and asks you to press a key. Then press any key and the window closes.
    • It installs Python 3.12 (into C:\Python\Python312), VS Code with the Python extension, and Git.
    • It also makes the folder D:\oss. Your own folder goes inside it (you make it in PART 1).
  6. When it is done, open install-result.txt in the same folder and read it. If any line says a tool is missing, raise your hand.
  7. Close every terminal window that was already open. Then open a new one: press the Windows key, type cmd, and press Enter. A terminal reads PATH at the moment it starts, so an old terminal cannot see the tools we just installed.
Install problem

If the window says FAILED, look in install-result.txt for the words DOWNLOAD FAILED, MISSING or NOT FOUND. A download did not finish, or a tool did not install. Double-click install.bat again. It keeps what is already done. If it fails a second time, raise your hand.

PART 2

Your first virtual environment

20 min

Build one box, put one library into it, and see with your own eyes that the box is separate from the rest of the computer. Screenshot 2 comes from here.

  1. In VS Code open a terminal: Terminal › New Terminal. It starts inside your folder. What is happening: the box will be made in the folder where the terminal is, so we start in your own folder.
  2. Make the box. It takes about 12 seconds, and a folder named .venv appears in the file list on the left. 
    python -m venv .venv
    What is happening: Python builds a new, empty box. The .venv folder holds its own python.exe and its own shelf for libraries. Nothing is on the shelf yet.
  3. Tell VS Code to use it. Press Ctrl + Shift + P to open the Command Palette, type Python: Select Interpreter, press Enter, and choose the one that has .venv in its path. It is usually at the bottom of the list, marked Workspace. Click it. If the top line already says .venv, it is already chosen — press Esc. Then go to step 4. What is happening: this PC now has two Pythons — one for the whole computer and one in your box. Here you tell VS Code which one runs your code. The name of the chosen one appears in the bottom-right corner.
  4. Open a new terminal again (Terminal › New Terminal). VS Code turns the box on by itself, and you see (.venv) at the left of the prompt. What is happening: a terminal keeps the settings it had when it opened. The old one does not know about the box; the new one opens with the box turned on. (.venv) means “you are inside the box now”.
    • Backup only, if (.venv) does not appear: type .venv\Scripts\activate in a cmd terminal.
  5. Install one library into the box. About 14 seconds. What is pip? Python’s tool for installing libraries. It comes with Python. pip install <name> downloads a library from PyPI (the public store of Python libraries) and installs it. pip list shows what is installed. What is rich? The project you toured in Chapter 2 (Textualize/rich). It makes text in the terminal look better — colours, tables, progress bars. We use it today because it is small, installs fast, and you can see it work with one line. 
    pip install rich==15.0.0
    What is happening: pip downloads rich and puts it on the box’s shelf only. ==15.0.0 fixes the version, so everyone in this room gets the same one.
  6. Look inside the box: 
    pip list
    You see a short list: rich, the small libraries that rich needs, and pip. This PC has pandas (a library for tables of data — you saw it in Chapter 2 and will use it in Chapter 9) and many other libraries installed for the whole computer, and none of them are here. That is what a virtual environment does.
  7. Screenshot 2. Press Win + Shift + S and drag over the terminal so that (.venv), the pip list command and the rich line are all inside the picture. Paste it into your issue now: open the issue, click … → Edit, paste under Screenshot 2, and save.
  8. Run one line and see the colour: 
    python -c "from rich import print; print('[bold green]hello[/]')"
    The word hello is printed in green. rich is the library you use again in Chapter 8. What is happening: the Python in the box finds rich on its own shelf and uses it. This proves the box works.
If pip list shows pandas

Then this terminal is using the whole computer, not your box. Look at the bottom-right corner of VS Code: it shows which interpreter is selected. Choose the .venv one again, and open one more new terminal.

PART 3

Three broken files, and AI reads them for you

30 min

You cannot practise asking about an error until you have one. So we make three, on purpose. Each one is a different kind of error, and each one takes five seconds to type.

Type each file yourself. Do not copy and paste it. Typing is how you notice the missing character. One trap: VS Code types the closing ) for you. In bad1.py, delete that ), save the file, and then run it.

FileType exactly thisThe error you should get
bad1.pyprint("hello"SyntaxError — a closing bracket is missing
bad2.pyimport ricModuleNotFoundError — there is no library with that name
bad3.pyopen("data.txt")FileNotFoundError — that file is not in this folder

Do steps 1 to 6 for each of the three files, one file at a time. Step 7 is done once.

  1. Make the file in VS Code (File › New File…, save it with the name above, inside your folder) and type the one line.
  2. Run it in the terminal: python bad1.py — then read what comes out.
  3. Select the whole error text with the mouse and copy it. All of it, including the file name and the line number.
  4. Open your AI tool and paste the error. Under it, add one line about what you were trying to do. Send it. For example: bad1.py — “I wanted to print the word hello.” · bad2.py — “I wanted to use the library rich.” · bad3.py — “I wanted to open a file called data.txt and read it.” Simple English is fine. What is happening: the error says what broke. Only you know what you wanted. Without your line, the AI can only guess.
  5. Read the explanation. Then ask the second question: "Why does the new code work?"
  6. Fix the file and run it again. Then say to yourself, in one sentence and in your own words, why it works now.
  7. For one of the three files, fill in the AI practice log in your [Ch03] issue now: open the issue, click … → Edit, write the four parts, and save. “Why it works now” is the graded part.
Which AI tool

ChatGPT, Gemini or Claude — whichever one opens in this browser. Try ChatGPT first; it answers without signing in. If one of them does not open, use another. If none of them opens, tell the instructor at once.

The test at the end
