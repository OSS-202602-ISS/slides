Promise

This course isn't a contest of coding skill. It's about building a real habit: finding, evaluating, using, and documenting good code that already exists.

Starting with a question

How much open source
is already around you?

  • Your Android phone — the Linux kernel (the core part of an operating system) is at its center. So its core is open source.
  • The Chrome browser you have open — its code comes from the open source project Chromium.
  • The server behind the classroom projector, the university's academic system — almost certainly running on Linux.
  • VS Code and Python, which you'll use this semester — both open source.

This semester, you will not just use open source. You will take part in it.

Definition

Visible source code doesn't
automatically mean open source

What separates open source isn't whether the code is visible — it's what the license permits.

source available

Code visible, no rights granted

You are only allowed to look. You often cannot change it, share copies, or use it in a product. This is not open source.

open source

Code visible + use, modify, and redistribute allowed

The license document clearly gives you these rights. That's why Chapter 7 of this course is about licenses.

Caution

Even if it's on GitHub and the code is visible, if there is no LICENSE file, you have no permission to use it. Normal copyright applies. Many people think "it's on GitHub, so I can use it." That idea is wrong, and it can cause real trouble.

Free Software Foundation

The Four Freedoms

The freedom to run the program for any purposeCan I use this for a class assignment? You do not even need to ask.
The freedom to study how it works and change itSo the source code must be open. Without it, this freedom is impossible.
The freedom to redistribute copiesHanding it to a friend isn't illegal.
The freedom to distribute your modified versionThe whole community benefits from the improvement.

Software that gives you these four freedoms is called Free Software. Open Source is the same idea with a name that businesses like better. The roots are the same, but the focus is different: Free Software talks about ethics. Open Source talks about building software faster.

1983 → Today

What happened over 40 years

1983

Richard Stallman announces the GNU Project. "I will build an operating system everyone can use freely."

1991

Finnish university student Linus Torvalds releases a kernel he built as a hobby. It becomes Linux.

1998

Netscape releases its browser source code. This leads to the name "open source" and to the OSI (Open Source Initiative).

2008

Android is released. Open source is now inside phones around the world.

Now

Most business software is built from open source parts. Knowing how to use them is a core job skill.

In 40 years, hobby code became the base of a whole industry. What you build this semester is a small part of that same story.

In your app

Parts inside your apps

A question

Why do companies give away
their own code?

Sharing the cost of maintenance

One team used to do all the bug fixes and security patches. Now users around the world share that work. Opening the code up is actually cheaper.

Setting the standard

If your approach becomes the industry standard, the services you build using it sell better. That's why Google made Android open source.

Attracting people

For the company, an open project is a job ad that never expires. For the people who contribute, their work is public — so it becomes their résumé. That is why your GitHub record counts in this course.

Earning trust

For security products especially, "verify it yourself" beats "trust us." It proves there's nothing to hide.

Through a security major's eyes

Visible code helps
and also creates risk

"Anyone can look at it" means both good people and bad people can read the code.

  • The people who find and fix vulnerabilities (weak points that let attackers in) also read the open code.
  • Every service in the world uses some of the same parts. So when one part is broken into, many services can be hit at once.
  • That's why simply knowing the list of "what you're using" becomes an important security task.
Coming up

In Chapter 10, we cover the Log4Shell and xz-utils incidents. Both put servers worldwide at risk at the same time. In both cases, the root cause was the same: "nobody knew what they were using."

The catch

"Using it" doesn't count if it becomes "copy-pasting it." To get credit, you must explain which part the library did. You must also explain which part you wrote. The same standard applies when you use AI.

STEP 0

Sit with people you know

5 min

You choose your own seat group. Sitting next to someone you know makes it easier to ask for help.

  1. Sit in one row — one row is one group of 3 or 4. Friends are fine; that is the point.

STEP 1

Create your GitHub account

20 min

This is an account you might use for 4, even 10, years. Choose your username especially carefully.

  1. Go to github.com/signup.
  2. Sign up with an email address you will still have after you graduate — a personal one is fine.
    • Your school email is needed only for the Student Developer Pack (STEP 3). You can add it later under Settings → Emails.
  3. Choose your username. This name becomes your address — github.com/username
    • Recommended: names close to your real name and easy to read, like hongildong-dev, gd-hong
    • Avoid: names like xXcutie_2026Xx. Choose it as if it's the address you'll write on a job application.
  4. Open the verification email to activate your account.
If you're stuck

If the verification email doesn't arrive, check your spam folder first. If it's still not there, click resend. The puzzle verification on the sign-up screen can be slow on the lab network, so give it a moment.

STEP 2

Turn on two-factor authentication (2FA)

10 min

For an account you push code to, you should always turn on 2FA. It is more trouble to set up later, so do it now.

  1. Go to your profile in the top right → Settings → Password and authentication.
  2. Install an authenticator app (Google Authenticator, Microsoft Authenticator, etc.) on your phone and scan the QR code.
  3. Be sure to save your recovery codes.
    • If you lose your phone, these codes are your only way back in. Screenshot them and keep them in the cloud or your email.
Warning

If you switch phones without saving your recovery codes, you lose the account entirely. This actually happens to students mid-semester. Save them now.

STEP 3

Apply for the Student Developer Pack

20 min

A set of free developer tools for students. Approval takes time, so today you only need to get to "submitted."

  1. Start your application at education.github.com/pack.
  2. Register and verify your school email on your account.
  3. If they need proof that you are a student, upload a photo of your student ID.
    • Make sure your name, school name, and expiration date are all easy to read in the photo. Most applications get rejected because the photo is blurry.
  4. Wait for the result after applying. Once approved, you'll unlock free perks like Copilot Pro.
Note

Not getting approved today doesn't affect the course at all. The perks are a bonus, not a requirement.

Mini Assignment #1 · 30 min

Find the open source in your phone

In today's lecture, we said "we're already using open source." This assignment helps you check that for yourself and bring back proof.

Assignment

What to submit

  1. Pick one app or service you use often.
  2. Find that app's open source license notice screen and take a screenshot.
  3. Along with the screenshot, write three lines.
    • Which app
    • The path you took to find it
    • One library name from the list that caught your eye, and why
Point

The goal isn't just finding the screen. It's about really feeling this: "wow, this app uses so much of someone else's code!" The longer the list, the better the discovery.

Hint

Where it's hiding

Menu names vary slightly by device and version. Use the table below as a starting point and look for a similarly named menu.

WhereApproximate path
AndroidSettings → About phone → Legal information → Open source licenses
iPhoneSettings → General → Legal & Regulatory
Individual appsIn-app Settings → About the app / About → Open source licenses
Chrome browserType chrome://credits into the address bar
Desktop programsHelp → About → Licenses, or the LICENSE file in the install folder
If you're stuck

If you really can't find the menu, switch to a different app. Popular apps like Instagram, Spotify, or your banking app usually have a notice screen too. If you still can't find one, Chrome's chrome://credits always works.

Screenshot

How to take the picture

The keys are different on every device. Find yours below.

DevicePress these at the same time
Android phonePower + Volume Down
iPhone with Face IDSide button + Volume Up
iPhone with a Home buttonHome + Side button
Windows PC (the lab PC)Win + Shift + S, then drag over the part you want
MacCmd + Shift + 4, then drag over the part you want
Then

On the lab PC: Win+Shift+S already copies the image, so click inside the issue box and press Ctrl+V. It uploads by itself. On your phone: the picture is in your gallery, and moving it to the PC is extra work — so just open github.com in your phone browser and write the issue there. You can attach the screenshot straight from the gallery.

Submit

How to submit

  1. Go to the practice-pr repository in the course Organization.
  2. Click Issues → New issue, then choose Chapter 1 submission.
  3. Finish the title: [Ch01] StudentID Name. The rest of the form is already written for you.
  4. Drag the screenshot into the box (it uploads by itself) and fill in the three lines.
- App: Instagram
- Path: Settings → About → Open source licenses
- What caught my eye: OkHttp — I'd never heard of it, but it was
  right at the top of the list. Turns out it's a networking library
  used by most Android apps.
Why

Why an issue (a page for reporting or discussing something), specifically? In real open source projects, every conversation starts with an issue. You'll keep using them from Chapter 2 on. That's why we start here, with your first assignment.

Grading

How it's graded

We don't look at coding skill. We only look at whether you did it, and whether you can explain it.

Complete

Both the screenshot and the three lines are present. You use your own words about the library that caught your eye.

Partial

The screenshot is there, but the explanation is missing or copied word-for-word from someone else.

Not submitted

No issue by the deadline. Late submissions still get partial credit.

Deadline

Before the next class starts. The goal is to finish within the 30-minute block, and if you can't, finish it at home.
