Licensing

A license answers one question:
“If I use this code, what must I do?”

Permissions

What you may do

Use it, change it, share it, use it in a product you sell.

Conditions

What you must do

Keep the copyright notice. Sometimes more. This is the part that matters today.

Limitations

What you do not get

No warranty. If the code breaks, the authors are not responsible.

When you may use someone else's code

Three licenses, one table

MIT, Apache 2.0, GPL 3.0:
what you must do

All three let you use, change and share the code, also in a product you sell. The difference is only in what you must do when you give your program to other people.

LicenseTypeWhat you must do when you share it
MITpermissiveKeep the copyright notice and the license text. That is all. You do not have to share your own source code.
Apache 2.0permissiveKeep the notices and give a copy of the license. Mark the files you changed. You also get a patent license from the contributors.
GPL 3.0copyleftKeep the notices and mark your changes. Your whole program must use GPL 3.0 too, and you must make its source code available.
Two words

Permissive (a license that asks for very little) — you keep a notice and do what you like. Copyleft (a license that must pass on to your program) — if you share a program that includes GPL code, your program must be GPL too.

Two files

LICENSE and THIRD_PARTY.md
are different files

LICENSE

The rules for your code

One file in the root of your repository. It says what other people may do with the code you wrote. GitHub reads it and shows the license name on the repository page. Today you add one to oss-practice.

THIRD_PARTY.md

The list of other people's code

Every library your project uses, with its version, its license and what you use it for. The team project template already has one — you fill it in for your own project.

| Library | Version | License | What we use it for |
|---|---|---|---|
| rich    | 15.0.0  | MIT     | Printing the result table in the terminal |
One sentence

LICENSE is what you give. THIRD_PARTY.md is what you took. A real project needs both.

The trap

No license means
you may not copy it

Many people think that public code with no license is free for everyone. It is the opposite. Code is under copyright from the moment someone writes it. A license is the permission. No license, no permission.

What GitHub allows

You can view it and fork it

Because the owner accepted GitHub's terms of service. That is all. It does not mean you may copy it into your project.

What you can do

Ask, or choose another one

Open an issue and politely ask the owner to add a license. Or choose another library that has one.

Your own repository

Your oss-practice has no license yet. Right now nobody may legally reuse your code. In the Lab tab, you change that.

PART B1

Add an MIT LICENSE to oss-practice

10 min

GitHub has a license picker. It writes the whole license text for you.

  1. Open your own repository: https://github.com/<you>/oss-practice.
  2. Above the list of files, open the Add file menu and click Create new file.
  3. In the file name field, type LICENSE — all capital letters, no extension.
  4. A button Choose a license template appears under the file name. Click it.
  5. On the left, choose MIT License. Check the line Copyright (c) <year> <name>: your name or your GitHub username is fine. No student ID. This repository is public.
  6. Click Review and submit. Then click Commit changes..., keep the message, and click Commit changes. What is happening: the template only filled in the text. Commit changes makes one new commit on main of your repository on GitHub, and that commit adds one file, LICENSE, at the top of the repository. Nothing on this PC changes.
  7. Go back to the main page of the repository. The license name now shows on the right side of the page. What is happening: GitHub reads the LICENSE file at the top of a repository, recognizes the MIT text, and shows its name in the About box. In the assignment you read this same box on other projects.
Your local folder is now one commit behind

You made this commit on GitHub, not on this PC. The next time you work in D:\oss\<your ID>\oss-practice, run git pull first.
