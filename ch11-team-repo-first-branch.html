Where the work is

One repository for each team

The instructor made ten repositories from the course template (the starting files): team-a-project to team-j-project.

The repository name has your team letter in small letters: Team C → team-c-project. .venv stays on the PC, because the file .gitignore lists .venv/.

  • No fork — Every member of a team can write to the team's repository. So you do not fork, and you do not make a new repository.
  • Why one per team — Every commit, issue and review on GitHub shows the name of the person who made it. So the repository also shows who did which part.

The rule for main

Nobody can push to main

In your team repository, main is protected: GitHub rejects a direct push. A change goes into main only through a pull request.

The approval comes from a teammate, because GitHub does not let the author approve their own pull request.

What a rejected push looks like

The push fails, and Git prints several lines. Look for these two parts:

Changes must be made through a pull request
! [remote rejected] main -> main

Nothing changed on GitHub. Lab PART 1, step 3 shows how to move your commit to a branch.
